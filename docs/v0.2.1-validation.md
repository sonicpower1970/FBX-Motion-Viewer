## Limits and manual checks

Windows/Linux and Intel Mac execution were not available here. Check actual native save dialogs, cancellation, filename/overwrite behavior and download fallback on target machines. WebCodecs H.264 support remains dependent on browser/OS/GPU. Future hosted deployments need HTTPS; localhost is already a secure context for this API. A denied native save request reports failure rather than bypassing the user's permission choice.

Fallback completion means the download has been handed to the browser; its final location/prompts are controlled by browser preferences. The MP4 still buffers in memory with a 512 MiB encoded-output cap; saving is not streaming. Cancellation during a pending disk write is applied before commit when that write returns. A file already committed (or a browser download already started) cannot be recalled.

Infinite Grid may lose precision at extreme world coordinates; grid settings have no UI yet. Ground height remains fixed per loaded asset/take. Existing Follow loop-boundary and shadow-volume limitations remain as described in `v0.2.md`. Existing build advisory for the >500 kB main chunk remains.

Manual acceptance: Follow off → move character out of view → Follow on; stable camera distance and user navigation afterward; grid horizon during long travel; all target export resolutions/FPS; playback/pose/camera/target/Follow restoration on save/cancel/error; old FBX Skeleton and Skinned Mesh with multiple takes.
