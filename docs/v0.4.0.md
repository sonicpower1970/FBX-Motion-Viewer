# v0.4.0 — Viewport Background and Still Image CAPTURE

v0.4.0 adds two review features while retaining the v0.3.0 animation, camera, single MP4 and batch workflows. Root Motion Trail, A/B comparison and FBX Info are not part of this release.

## Viewport background

The toolbar toggle shows the current **DARK / LIGHT** background. DARK is the default. This changes the viewport environment only; application controls retain their dark UI.

| Display helper | DARK | LIGHT |
| --- | --- | --- |
| Background | `#1c232b` / RGB(28,35,43) | `#b8b8b8` / RGB(184,184,184) |
| Grid minor / major | `#465361` / `#758492` | `#787878` / `#505050` |
| Bone start / end | `#ffe0a3` / `#dd9745` | `#754000` / `#a35400` |
| Burn-in text | `#f0f0f0` | `#20252b` |
| Burn-in outline | Black, alpha 0.8 | White, alpha 0.85 |
| Frame-guide outline | `#c4d3da66` | `#343a4080` |

LIGHT uses neutral gray rather than white so white meshes and highlights remain distinguishable. X-Ray uses the same bone palette without changing its depth behavior. Ground Shadow retains its black color and 0.32 opacity. Viewport labels and hints adjust for contrast. FBX materials, textures, animation, transforms, camera and lighting remain unchanged.

## Still PNG capture

**CAPTURE** sits beside EXPORT MP4 and works with animated or static FBX files. It captures the current camera and frame, including mesh/bone visibility, X-Ray, grid, shadow, background and optional burn-in. Capture never fits the camera, seeks another frame or updates/reinitializes Follow.

| Frame guide | PNG output |
| --- | --- |
| OFF | Full viewport at its CSS pixel dimensions, rounded to integers without Retina amplification or MP4 even-pixel rounding |
| ON | The centered 16:9 guide interior at **1920×1080** |

Guide lines, labels, toolbar icons, outside shading and application UI are excluded from the image. PNG is the only supported format; no additional resolution controls are introduced.

The renderer draws the same scene using a clone of the current Viewer camera. `exportCamera` / `applyExportProjection` share the MP4 gate projection. The live camera is not modified. A Canvas 2D composite copies the render immediately and uses `BurnInRenderer` for the overlay, then encodes a lossless PNG. This does not depend on WebCodecs or `preserveDrawingBuffer`.

Playback and navigation are temporarily locked during capture and saving, then restored on success, cancellation or failure. The animation clock resets its next delta so time spent in a save dialog does not create a playback jump.

## Burn-in and filenames

Viewer, PNG and MP4 reuse the same burn-in drawing path, filename auto-fit, safe margins and frame-number presentation. With the guide ON, relative text positions and sizes match the guide interior. At 1080p the nominal text size is 24px and safe margin is 32px. Long names shrink, with middle ellipsis when needed.

- Animated FBX: `walk.fbx`, current frame 25 → `walk_f0025.png`.
- Static FBX: `prop.fbx` → `prop.png`.
- Only the source basename is used; parent paths are removed.
- Frame digits have a minimum width of four and expand as needed. Timeline, burn-in and capture names use the shared `displayFrame` / `endFrame` / `formatFrame` rules, including future start-frame offsets and partial end frames.
- Static FBX burn-in shows filename only in both Viewer and PNG, avoiding the former `0000 / 0000` counter. Static MP4/batch export remains unavailable under the existing animation requirement.

## Saving

Supported browsers open the Save File Picker during click activation with a suggested PNG filename. Dialog cancellation is a normal outcome. Other browsers use Blob download. PNG reuses the existing MP4 writable-stream commit, abort and download handling. Permission or disk errors are reported without silently choosing another destination.

## MP4 and batch behavior

Single MP4 uses the selected viewport background. Batch inherits that selection when its panel opens and applies it to each isolated job. Existing callers default to DARK.

Batch FIT + FOLLOW, default take, FPS AUTO, 720p/1080p, burn-in, sequential processing, folder selection, cancel, retry failed, collision-safe filenames and Viewer isolation remain unchanged. No new batch controls or dependencies are introduced.

PNG uses the current composition. MP4 retains its existing FIT-at-START and Follow-rebase policy. Image comparisons therefore require the same evaluated frame **and camera**. Matching manual FOLLOW composition at an intermediate frame was checked by decoding the actual MP4 frame. A FIT ON MP4 can refit START; capture intentionally does not perform that operation.

## Validation and compatibility

The maintainer confirmed successful macOS Apple Silicon + Chrome hardware testing before public release preparation. Development validation passed lint, typecheck, unit tests, normal/Pages builds, Chrome regression and nested-path Pages tests. Existing legacy loading, playback, camera restoration and batch regression remain covered.

Capture tests cover DARK/LIGHT, skeleton-only, mesh-only, skin, animated/static FBX, public legacy fixtures, guide OFF/ON, burn-in OFF/ON, long names, FOLLOW, Full HD, save/download/cancel/failure, Retina DPR 2, visibility and save-dialog state locking. Generic fixture paths and public upstream metadata are intentional test data, not private production assets.

The six generated package ZIPs retain licenses and matching Mediabunny source. macOS Intel, Windows x64/ARM64 and Linux x64/ARM64 packages are provided but have not been hardware-tested in this development environment.

Native file dialogs, browser permission flows, fonts and GPU/DPI behavior still need acceptance on each target machine. Public legacy FBX 6100 fixtures are covered; optional production FBX 6000 tests require an external local sample. PNG and MP4 can differ in grid antialiasing, text rasterization and H.264 compression while sharing camera composition.
