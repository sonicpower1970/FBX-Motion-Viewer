# v0.2.7 — FIT toggle and Follow loop rebasing

## Confirmed specification

The initial request simultaneously required an unchanged camera world position at a loop boundary and no change in camera/subject relative position when the root resets. Those cannot both hold for non-cyclic root motion. The user confirmed prioritizing **relative composition**: at END→START, translate camera and Orbit target by the same correction, without Fit, rotation, lens or distance changes.

FIT and AUTO FIT are now one FIT toggle, default ON. OFF→ON fits the current pose once and enables subsequent automatic Fits. ON→OFF leaves camera and Follow history intact. FOLLOW remains independent. F retains its existing one-shot Fit shortcut without toggling the mode. There is no separate AUTO FIT button.

| FOLLOW | FIT | Loop | Export START |
|---|---|---|---|
| OFF | OFF | Fixed camera | Fixed camera, no Fit |
| OFF | ON | START Fit | START Fit |
| ON | OFF | Relative-composition loop rebase, no Fit | Keep user camera; initialize START reference, then Follow |
| ON | ON | START Fit and reference reset | START Fit and independent Follow |

As before, loading a new FBX fits only when FIT is enabled; turning FOLLOW on fits only when FIT is enabled. Normal playback/scrub/step never continuously fit.

## Drift cause and correction

v0.2.6 already reset the previous root position at START. However, it retained the camera displacement accumulated during the previous cycle while the character returned to its original world position. Each further cycle added the same net travel again. Resetting the previous root position alone therefore could not stop this drift.

`FollowController.rebaseLoopPreservingComposition()` runs after exact START evaluation. It computes START minus the **last actually evaluated** root position, projects onto the ground-follow plane, translates camera and Orbit target together, then resets the reference. It does not assume the exact END sample was rendered. The engine subsequently evaluates the modulo time remainder and applies ordinary Follow. This handles skipped END samples, uneven frame timing and updates crossing multiple loops.

No cumulative-loop offset is stored. `resetFollowReferenceWithoutMovingCamera()` is separately used after Fit and at Export START. Ordinary `update()` remains shared by playback, scrub and offline export; loop correction is explicit and separate. Non-finite positions/deltas are discarded and the reference safely resynchronizes; legitimate finite backward scrubs continue to follow motion.

Ground-only behavior is preserved: jumps/vertical motion do not make the camera follow Y. Relative **ground-plane** composition and camera–target distance remain stable; a changing vertical subject pose can still change its 3D distance to the camera. At the boundary the world/grid can visibly shift as camera and character return together; this is the confirmed policy, not in-place or cumulative-root animation.

Export is unchanged in principle: exact-time offline frames, FIT ON optionally fits START, FIT OFF preserves the saved camera and initializes only a START reference. It does not execute a playback loop. Projection matching, guide-aware Burn-in, save picker/fallback and original-state restoration remain intact.
