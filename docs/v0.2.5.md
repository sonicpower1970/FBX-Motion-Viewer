# v0.2.5 — Camera rules and matching guide composition

## Camera rules

FIT remains a one-shot command with no mode state. When a guide is visible, FIT uses its contained framing angles while keeping the live camera's viewport aspect/projection. The guide toggle itself never fits, moves or modifies the camera.

FOLLOW OFF: playback/loop never fit or move the camera. Export copies position, orientation, target and zoom. It samples animation from START without refitting. Only the output projection is adapted to the chosen image area.

FOLLOW ON: enabling Follow fits the current posed bounds once. A loop evaluates exact START, fits once, resets the baseline and applies any wrapped-time remainder normally. Export uses an independent camera/Follow baseline: exact START evaluation, one Fit, then deterministic per-output-frame motion. No rAF or playback speed drives export.

Time, playback, camera position/quaternion/zoom/projection, target and Follow internal state restore after export, cancellation or error. If the viewport did not resize, the saved projection matrix/inverse are preserved without an unnecessary recalculation. If resized during export, camera aspect adapts to the new viewport as before.

## Projection and layout

For viewer aspect A and output aspect R=16/9, the largest contained guide has height fraction `k = min(1, A/R)`. Export vertical FOV is `2*atan(tan(viewerFov/2)*k)`; aspect becomes R and zoom remains unchanged. Thus a scene point's position relative to the guide equals its normalized output position, including in portrait and very wide viewports. Positions/Orbit target are never moved just to achieve this projection match. The same crop policy applies to fixed 16:9 output even with the guide hidden.

Guide-aware FIT uses the same contained angular limits. Therefore a START pose fitted into the visible guide and the same START pose fitted for Follow export produce matching camera positions. FOLLOW ON still intentionally refits START: an arbitrary pan/dolly or Fit made at a different pose cannot be preserved simultaneously with this required START refit. For a fixed manually composed shot, use FOLLOW OFF; for a Follow preview, return to START with Guide ON and press FIT before reviewing the take.

`frameRect` is the common contained-area calculation for burn-in. Guide OFF: entire preview viewport. Guide ON: centered guide rectangle, including filename measurement, minimum font size, safe margins and counter alignment. The overlay is clipped to that rectangle. MP4 uses the whole output frame for burn-in. Current Viewport retains its full-viewport image and full-frame burn-in even if the guide is visible; it is never forced to 16:9. Existing odd-pixel rounding for AVC can alter its ratio by up to one pixel.

BURN-IN remains one toggle. Frame Guide remains the original SVG toggle/tooltip/pressed state from v0.2.4. Guide border, corner icon and outside tint are never encoded. No HTML capture or real-time recording is used. Basename-only text, long-name fitting, legacy FBX/WASM and texture privacy remain unchanged.

## Limits / manual acceptance

Composition matches geometrically, not byte-for-byte: resolution, antialiasing, font hinting and H.264 compression can change pixels. Extremely long filenames can reach different final glyph rasterization at different sizes. Follow START Fit and Current Viewport's full-frame policy are deliberate behaviors described above. Existing large-scene memory, fixed shadow range, rig target selection and WebCodecs/GPU limits remain. Other OS native execution still requires real-machine acceptance.

Check: FOLLOW OFF with arbitrary pan/orbit/zoom over multiple loops and export; FOLLOW ON over repeated loops and exports from START/middle/end; START Fit with Guide ON; short/long/Japanese Burn-in names within the guide after resize; guide-vs-1080p character framing and text margins; Current Viewport retaining its full aspect; exact original state after success/cancel/failure. Repeat with legacy Skeleton and Skinned Mesh / multiple takes on Windows/macOS/Linux Chrome.
