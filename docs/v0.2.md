# v0.2 review and preview export

Camera rules below describe their historical versions. Current FIT/FOLLOW UI and loop behavior is specified in [v0.2.7](v0.2.7.md); Export composition is updated in [v0.2.8](v0.2.8.md).

## Compatibility checkpoint

The verified v0.1.1 checkpoint was preserved in the private development history. That history and its tags are not included in the public repository, which starts at v0.3.0. Ordinary builds use the included generated WASM; no C toolchain is needed.

The Three.js/FBXLoader version, version routing, ufbx source/bridge, WASM and texture policy are unchanged in v0.2. No FBX or motion data is uploaded. Existing tests remain enabled, including the optional local production FBX 6000 regression.

## Playback and display

- Playback speed: 0.25×, 0.5×, 1×, 2×. Only real-time clock advancement is multiplied. Frame steps, scrub seconds, Timeline FPS and export timestamps remain unchanged.
- X-Ray disables SkeletonHelper depth testing and draws bones after meshes. It never changes the separate Bones visibility switch. Default: off.
- Shadow adds a transparent, shadow-only ground plane and a 2048² PCF directional shadow map. Single-sided meshes also cast shadows. Meshes retain their original transforms and animation.
- Ground/shadow bounds are initialized from the current asset/take's posed bounds with generous padding. The ground height stays fixed, while its XZ center and light volume follow the chosen subject node. Bounds are not recomputed every frame. Extremely large pose changes/jumps can exceed this fixed volume. Initial ground height is just below the initial posed minimum Y; there is no ground-height editor yet.

## Follow

The Viewer scene and camera use Y-up. `FollowController` supports `off | ground | 3d` internally; v0.2 exposes only off/ground.

A stable scene node is selected, not a bounding-box center. Prefer the largest skeleton and its shallowest bone with varying translation in the selected clip. Otherwise use its root bone; mesh-only scenes use an animated transform or first mesh. World positions include animated ancestor transforms. Multiple independent characters or unusual rigs may need manual target selection in a future version.

On the OFF → ON transition, fit the current posed bounds once, then record that node's world position. After playback, scrubbing or stepping, project its displacement onto XZ, then add the same delta to camera position and Orbit target. Camera orientation, distance, lens and zoom are not refitted. User Orbit/Pan/Dolly/Zoom offsets remain intact. Fit still frames the current pose and rebases Follow. A new take establishes a new reference without an automatic camera jump.

At a playback loop boundary (v0.2.2), evaluate the exact START pose, fit once and reset the Follow baseline there. Then evaluate the wrapped time remainder and apply ordinary ground displacement. Never feed END→START displacement into Follow. This resets accumulated pan/dolly offsets at each loop, while retaining the current viewing direction/lens. No per-frame Fit is performed. If a slow playback update crosses multiple loops, only the final visible loop requires fitting.

## MP4 preview

1. Select the take, Timeline FPS, camera, Follow and display settings.
2. Choose 1280×720, 1920×1080, or Current Viewport.
3. Click EXPORT MP4. Where supported, choose a destination and filename before rendering starts. Cancelling this picker does not start encoding. Otherwise a normal browser download starts automatically after encoding. There is no second download button.

WebCodecs H.264 encoding and mediabunny 1.59.1 MP4 muxing run locally. Offline ZIPs include the matching unmodified mediabunny source and MPL-2.0 license in `third-party-sources/mediabunny`. There is no MediaRecorder, screen capture, real-time recording, audio track or ffmpeg.wasm dependency. Unsupported resolution/FPS/encoder combinations produce an error; try 720p or another Chrome installation.

Each output frame is computed from its integer index. The selected take is sampled from zero through its exact end, and the end pose is held for one output frame. With duration D and rate F, frame count is `ceil(D × F) + 1` (with the same integer-boundary tolerance as the timeline). Sample time is `min(i/F, D)`, output timestamp is `i/F`, each output duration is `1/F`. Thus a 2-second take at 30fps has 61 frames and a 2.033333-second MP4. An off-grid endpoint is clamped to D. Fractional rates use 24000/1001, 30000/1001 and 60000/1001. Playback speed does not change export speed: previews use original animation time (1×).

In v0.2.5, 720p/1080p clone the camera position/rotation/zoom and derive export FOV/aspect from the centered contained 16:9 guide crop. Current Viewport retains full-viewport framing. Current Viewport means actual rendered canvas pixels (including the current device-pixel ratio, capped at 2); odd dimensions round down by one pixel for AVC. UI and Frame Guide overlays are not encoded; enabled Burn-in is composited into the output. Mesh/Bones/X-Ray/Grid/Shadow switches affect the image.

In v0.2.2, Follow export uses an independent camera/target and freshly initialized Follow history. After save destination selection, seek to exact START, fit its posed bounds once using output aspect and current viewing direction/lens, and reset the export Follow baseline. Frame-index sampling then advances this camera deterministically. Current frame, previous pan/dolly offsets and live Follow history do not affect this initial Fit. Follow OFF continues using the current Viewer camera without a start Fit. Every render is immediately captured and `CanvasSource.add()` is awaited before proceeding; no real-time clock or requestAnimationFrame drives export.


The live playback loop and controls are suspended while exporting. The original animation time, playing state, camera position/quaternion/zoom, Orbit target, Follow mode and reference, controls and renderer size/pixel ratio are restored in `finally` on success, cancellation and errors. If the browser window was resized, the restored camera aspect follows the new viewport.

The MP4 is held in memory, then written to the selected file (committed on stream close) or handed to the browser download manager. The default filename preserves the FBX basename with an .mp4 extension. Browser download location/prompts follow browser preferences. Cancelling before commit aborts the write; a committed file/download cannot be recalled. Progress reports completed/total frames and percentage, followed by Export complete / Export cancelled / Export failed. The export button stays disabled throughout selection, encoding and saving. Encoded output is limited to 512 MiB; peak memory can exceed that limit due to muxing and the existing scene. There is no streaming-to-disk export yet. GPU/encoder failure or closing the page can prevent completion. Codec availability and performance vary by OS/GPU/Chrome. No automatic external fallback is used.

## Validation and manual acceptance

Automated coverage includes:

- speed-independent stepping at all four speeds;
- Follow ground deltas, vertical rejection, user offsets, step/scrub, off mode, multiple-loop reset and future 3D mode;
- independent Bones/X-Ray visibility and shadow range/ground invariants;
- exact export sampling for all eight FPS settings;
- actual Chrome MP4 generation at 720p/30 and 1080p/23.976, packet counts/timestamps, no audio;
- Follow movement in the export camera and exact successful/cancelled/failed state restoration;
- original modern and legacy file/skin/take/texture/navigation/replacement regressions;
- optional production FBX 6000 full-take export (933 frames) with Follow;
- the extracted offline Mac package, including legacy loading and MP4 export without external requests.

On real target machines, check:

1. Maya and MotionBuilder walking/running clips: target selection, ground-only following, manual orbit/pan/dolly, scrub/step, Fit and non-cyclic loop behavior.
2. Jumping mocap: camera Y remains fixed while bones rise/fall.
3. Mesh/Bones/X-Ray combinations, and Shadow on/off with small/large/skinned/thin meshes. Check shadow coverage on extreme poses.
4. Every resolution and FPS needed in production, including 59.94/60 and long clips. Confirm final pose and output framing in a media player.
5. Export while paused and playing; cancel midway and verify the original time/camera/Follow resume correctly.
6. Old FBX 6000/6100 and current FBX files; other takes, missing/embedded textures, repeated loads.
7. Windows/Linux and Intel Mac Chrome codec/GPU behavior, and 500 MiB scenes. These machines/workloads have not been tested in this environment.

## v0.2.1 UX changes

- InfiniteGrid renders a four-vertex screen quad and intersects rays with the Y-up ground. Major/minor lines are antialiased and fade with distance before camera far clipping. Grid remains world-anchored as the camera moves, including during export. No FBX transforms change and no large world geometry is allocated.
- `GridSettings` exposes spacing, majorInterval, fadeDistance (0 = adaptive), and height. Initial spacing comes from asset extent; height matches the fixed shadow ground. These settings are not yet exposed in the UI. Extremely large coordinates remain subject to GPU floating-point precision.
- File saving is isolated in `src/export/saveExportedVideo.ts`. Feature detection uses `typeof window.showSaveFilePicker === 'function'`; no OS detection, platform paths, native applications or server upload are used. The picker is invoked in the original click activation before asynchronous imports/encoding, as required by [Chrome's File System Access documentation](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access). Localhost is supported; a future online deployment needs HTTPS. API availability does not guarantee permission: denied permission/write errors are reported rather than silently overriding user intent.
- Manual acceptance: move the subject offscreen with Follow off, then enable Follow; check a single fit and stable distance afterward. Pan/orbit far beyond the original grid and inspect horizon/major/minor lines. Test native save, filename, picker cancellation, file overwrite/disk failure, ordinary download fallback, progress and original viewer state after every outcome on each target OS.

## v0.2.2 Frame Guide

The four-corner Frame Guide icon toggles a centered HTML overlay using the largest exact-aspect rectangle contained by the viewport. ResizeObserver tracks its size. It has no pointer events and never enters the WebGL scene, changes camera aspect, selects export resolution or appears in the MP4. The ratio catalog and geometry utility are separate for future formats.

720p/1080p use the centered 16:9 crop projection in v0.2.5; Current Viewport uses its own rendered-pixel aspect (including existing even-pixel rounding). The guide is an accurate projection preview for the same camera and pose. Follow ON still performs the requested START Fit, so arbitrary current pan/dolly or fitting at a different pose can change composition. See [v0.2.5](v0.2.5.md) for the camera rules, shared Burn-in region and validation.
