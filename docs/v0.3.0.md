# v0.3.0 — Batch FBX → MP4

## 実装範囲

Batch Exportのみ追加。Root Motion Trail、A/B比較、FBX Info等は未実装。Single Viewer／Single Exportの仕様、旧FBX変換WASM、Mac .app／.commandランチャーを維持します。追加npm依存はありません。

## Architectureと共通化

`BatchController`がQueueを1 Jobずつawaitして処理します。Jobごとに画面外の960×540ホストと既存`ViewerEngine`を新規作成し、既存`load()` → `prepareBatch()` → `exportMovie()`を呼び、finallyでEngineとホストを破棄します。新しいFBX Renderer／Mixer／FIT／FOLLOW／Burn-in／Encoderは作っていません。

`exportMovie(resolution, destinationOverride?)`へ保存先の任意引数だけを追加しました。Singleは省略し、既存Save File Picker／Download fallbackを使用します。Batchは選択済みDirectoryへ保存するhandleを渡し、各JobのSave Dialogを省略します。時間評価、Export用Camera clone、Guide投影、Follow更新、Canvas合成、mediabunny処理は同じ関数です。

通常ViewerのEngineはそのまま保持し、Batch Panelが開いている間だけ描画ループと操作を停止します。閉じると再開し、経過した実時間をAnimationへ加算しません。Camera・素材・Timeline・設定をBatch Engineへ流用しないので、元のViewerへBatchの状態が混入しません。

Batchは常に初期Camera方向・初期表示設定から開始します。Mesh/Bones/Grid ON、X-Ray/Shadow OFF。通常Viewerの手動構図や表示設定は継承しません。ResolutionとBurn-inだけがBatch共通オプションです。

## FPS調査と取得

v0.2.8のTimelineは初期30fps＋ユーザー指定であり、AnimationClipからFPSを推測していませんでした。このSingle仕様は維持しました。

`readFbxFrameRate()`を既存FBX読み込みのArrayBufferに対するメタデータ専用処理として追加しました。Scene構築やAnimation評価には介入しません。

- 現行・旧Properties形式のGlobalSettings：TimeMode、CustomFrameRate。Objects内の旧GlobalSettingsにも対応。
- 旧Settings／Version5→Settings：明示されたFrameRate（数値または文字列）。
- Binaryは32-bit／64-bitノードヘッダーを認識し、対象外ノード・配列をオフセットで飛ばします。ASCIIは行ごとに読み、巨大な文字列コピーを避けます。
- 現行のTimeModeを対応FPSへ変換。23.976／29.97／59.94は既存Timelineと同じ24000/1001、30000/1001、60000/1001を使用。
- Animationのキー間隔、キー数、Bake周波数からは推測しません。TimeSpanからもFPSは推測しません。Clipの秒単位Durationは既存Loaderの評価結果を使います。
- メタデータなし、不明なTimeMode、壊れた・読み取れないメタデータ、無効なCustom FPSなどは30fps fallbackとして明示。検出可能な標準FPSや正のCustom値（1000fps以下）は維持し、Encoderが非対応ならJobをFailedにします。
- 特殊なASCIIレイアウト（複数行に分かれたプロパティ値、64KiB以上の単一メタデータ行等）は対象外となりfallbackする場合があります。

現行TimeModeの根拠：[Autodesk FbxTime](https://help.autodesk.com/cloudhelp/2020/ENU/FBX-API-Reference/cpp_ref/class_fbx_time.html)。旧Settingsの扱いは同梱`vendor/ufbx/ufbx.c`の`ufbxi_read_legacy_settings()`に合わせています。

重要：実制作のFBX 6000では旧Settings内に`TimeMode: 3`と`FrameRate: "30"`が併存します。旧TimeModeを現行列挙値として読んだ60fpsは誤りなので、明示された旧FrameRateの30fpsを採用します。旧変換の120Hz Bakeは出力FPSを意味しません。WASMや変換ロジックそのものは変更していません。

AUTO FPS → Batch EngineのTimeline FPS → Frame Sampling → MP4 Encoderへ同じ値を渡します。FPS変更は秒単位のDuration／再生速度を変えません。最後の姿勢も1出力Frame含める既存仕様なので、出力Frame数は`ceil(duration * fps) + 1`、動画尺はそのFrame数/FPSです。Frame Counterは0から開始します。

v0.3.0はAUTOのみ。Manual Overrideは未実装。QueueのFPS・Framesは各Jobを読み込んだ時点で表示します。全素材の先読みはしません。

## Job初期化とMP4

新しいEngine／Camera／Orbit Target／Mixer／Follow履歴 → FBX Load → 先頭（既存Default）Clip → FPS設定 → FIT ON／FOLLOW ON → START評価 → 共通ExportのSTART FIT → Follow基準初期化 → 各出力Timeを明示的に評価 → Render／Burn-in／Encoder → 保存。

複数Takeを別々に出力する機能はありません。Default TakeにAnimationがない場合はそのJobをFailedにします。解像度は1080p（初期値）／720pのみ。Burn-inは初期ONで、既存basename／長い名前のFont Fit／Frame Counterを再利用します。UI、Frame Guide、音声はMP4へ入りません。

## Folder、失敗、Cancel、Retry

SELECT FOLDERのクリック中に`showDirectoryPicker({mode:'readwrite'})`を呼びます。API非対応なら明確な説明とともに開始を無効化します。SingleのDownload fallbackは変更しません。

出力名は元のbasenameから生成し、既存ファイルがあれば連番を付けます。ファイルの作成・writeはEncoder完了後です。同じフォルダに別アプリから同時作成する場合の原子的な排他作成までは保証しません。保存権限喪失／容量不足／Load／Encode失敗はJobにエラーを残し、次のJobへ進みます。

RETRY FAILEDはFailedだけを再実行し、成功済みは処理しません。選択したResolution／Burn-in／Folderを再試行へ使用します。CANCEL BATCHはLoad用AbortControllerと共通ExportのAbortControllerへ通知し、現在の処理を安全なポイントで止め、finallyで破棄します。未開始JobはCancelled。完成してclose済みの動画は削除しません。Cancelと保存commitが重なり保存済みならDoneとして扱います。CancelledはSTART BATCHで再試行できます。

保存失敗／中断のタイミングによって、作成済みの空ファイルが残る場合があります。再試行はその名前を上書きせず新しい連番へ保存します。通常の成功時は入力名と同じMP4名です。

## Resourceと長時間処理

常にBatch Engineは最大1個。通常Viewerの既存素材は保持しますが描画は停止します。

Job finallyでAssetInstanceがMixer、SkeletonHelper、Geometry、Material、Texture、Skeletonを解放。EngineはGround/Shadow、Grid、Burn-in Canvas、WebGLRenderer、ResizeObserver、Navigation/Event Listenerを解放し、WebGL Contextも明示的に解放します。ホストDOMを削除します。旧FBX workerは受信／失敗／Cancel時に終了し、埋め込みTextureのObject URLも既存処理で解放されます。共通ExporterがCanvasSourceを閉じ、失敗時はOutputをcancelします。

Queueは再試行用のFile参照と小さな進捗・結果情報のみ保持し、SceneやMP4 Blobを蓄積しません。CLEAR QUEUE／Panelを閉じる操作でQueueを破棄できます。Browser／GPU Driverの実際のメモリ回収タイミングは保証できません。50〜100本の大容量実制作素材は実機で追加確認してください。

## 制限と実機確認

1入力500MiB・1出力512MiBの既存上限を維持します。出力はJobごとにメモリ上でMP4化してから保存する方式で、ディスクへの逐次Muxは未実装です。

macOS／Windows／Linuxで同じWebコード。Chrome／Chromium、localhost、WebGL2・H.264 WebCodecs・Folder Accessが必要です。OSネイティブFolder APIは使用していません。ディレクトリ権限ダイアログとディスク書き込みは実機で確認してください。BrowserがバックグラウンドTabを制限すると処理が遅くなる場合があります。タブを閉じたり再読み込みするとQueueは失われます。

1. BATCH EXPORT → 3本の異なる尺のFBXを選択／Drop → SELECT FOLDER → 1080p・Burn-in ON → START BATCH。
2. 出力MP4のFPS、尺、先頭Frame、被写体のScale、Root Motion Follow、Filename／Counterを確認。
3. 24／29.97／30／59.94／60fps、FPS情報なし、旧FBX 6000を混在させてQueueの検出表示を確認。
4. 720p・Burn-in OFFも確認。同名出力を残して連番保存を確認。
5. 壊れたFBX、保存権限や容量エラーを含め、次のJobへ継続・RETRY FAILEDで成功済みを再処理しないことを確認。
6. Load／Export途中のCANCEL BATCH。完成済みMP4を維持し、残りが開始されないことを確認。現行FBXの同期parse中はCancelが遅れる既存制限があります。
7. Close後、通常ViewerのFrame・Camera・再生／表示設定・Single Exportを確認。
8. 10本、その後50〜100本で実ブラウザのRAM／GPUメモリと長時間の安定性を確認。
